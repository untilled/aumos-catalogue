# alpaca

Alpaca의 Market Data API. 키는 한 번만 입력하고, 호출은 에이전트가 합니다.

하나의 id, 하나의 자격증명, **두 개의 반쪽** — 그리고 그 반쪽들은 당신이 입력할 일이 아니라
우리가 알고 있을 일입니다. #232 전까지 이 벤더는 같은 호스트와 *같은 키 쌍*을 쓰는 두 소스
(시세용 `alpaca-market`, 헤드라인용 `alpaca-news`)였습니다. 그래서 Aumos는 Alpaca 키를 두 번
묻고 두 이름으로 보관했습니다.

## 무엇을 얻는가

| | |
|---|---|
| **닿는 곳** | `data.alpaca.markets` |
| **비용** | Alpaca 계정(모의든 실계좌든)만 있으면 무료 |

### 엔드포인트 — Alpaca 자신의 응답을, 읽지 않은 채로

```
/v2/stocks/bars       ?symbols,timeframe,start,end,limit,feed,adjustment,sort,page_token
/v2/stocks/snapshots  ?symbols,feed
/v1beta1/news         ?symbols,start,end,limit,sort,include_content,page_token
```

Aumos는 요청에 서명하고, 이 목록 밖의 경로를 거부하며, Alpaca가 보낸 것을 그대로 돌려줍니다.
**답이 어떤 모양이어야 하는지는 당신 에이전트의 일입니다.** 여기서 우리가 날짜를 붙이는 것은
없고, 판단 시점에서 잘라내는 것도 없습니다 — 이 엔드포인트를 읽는 에이전트는 자신의 시점 고정
원칙을 스스로 책임지며, 수정주가 봉을 요구하든 한 번에 100개 종목을 요구하든 기사 본문을
요구하든 자유입니다. 아래의 매핑된 반쪽은 그중 무엇도 해주지 않습니다.

### 매핑된 반쪽은 이제 없습니다

⚠️ 이 절에는 같은 자격증명을 읽어 날짜가 붙고 `asOf`로 잘린 행을 주는 **`market` 포트**와 내장
**`news` 포트**가 *얼어 있고 여전히 참인* 것으로 적혀 있었습니다. #232이 포트 레이어를 없앴으므로
둘 다 존재하지 않습니다: 여기서 매핑되는 것은 없고, Aumos가 날짜를 붙이지도, 판단 시점에서
자르지도 않습니다. 위의 엔드포인트가 이 문서가 제공하는 전부입니다.

## 시세 소스 둘을 동시에

**엔드포인트**를 호출하는 에이전트는 이것과 `openbb-fmp`를 함께 써도 됩니다 — 소스를 이름으로
지목하므로 둘 사이에서 정할 것이 없습니다.

**`market` 포트**를 요구하는 에이전트는, 두 문서가 같은 거래소를 선언한다면 그럴 수 없습니다:
`market_history`는 소스가 아니라 자산을 받으므로, `XNAS`를 주장하는 두 벤더는 어느 쪽이 답했는지
말해줄 것을 남기지 않고, 증거는 정확히 하나만 기록합니다. 그 거부는 얼어 있는 반쪽의 것이고,
엔드포인트가 존재하는 이유이기도 합니다.

## 당신이 제공하는 것

Alpaca의 키 id와 시크릿, 한 번. 작성자 기본값은 없고 있어서도 안 됩니다 — API 키는 누구도 남에게
줄 수 있는 것이 아닙니다. 설정 → 데이터 소스에서 입력하면, Aumos가 시스템 키체인에 보관하고 어떤
에이전트도 그 값을 보지 못합니다.

입력하기 전까지 이 소스는 자기 호출을 이름과 함께 거부합니다. 나머지 도구가 동작하는 것을 막지는
않습니다.
