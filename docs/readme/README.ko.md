# aumos-catalogue

<sub><a href="../../README.md">English</a></sub>

[Aumos](https://aumos.app) 카탈로그의 제출 경로. 여기서 두 가지가 발행되고, 둘 다 코드를
담지 않는다.

**ManagerPackage**는 산문으로 쓴 투자 방법론이다. 어떤 데이터를 읽어도 되는지 선언하는
manifest, 그리고 어떻게 추론하는지 적은 프롬프트 번들. 발행 형식이 파일 경로를 텍스트에
대응시킨 JSON 문서라, 실행파일이 들어갈 필드 자체가 존재하지 않는다.

```
managers/
  your-package-id/
    aumos.json                  무엇을 읽어도 되는지, 그리고 저자가 대는 각각의 이유
    PROMPT.md                   방법론. 파일 하나이고, 진입점이다
    README.md                   어떻게 추론하는가 — 사람이 보고 고르는 페이지
    .claude-plugin/plugin.json  `runtimes`에 `claude`가 있으면 필수
    skills/…/SKILL.md           선택 — PROMPT.md가 필요할 때만 읽어 들이는 것
    icon.svg                    선택 — 카탈로그 카드의 마크
    config.schema.json          선택
    README.ko.md                선택 — 옆에 translations/ko.json과 함께
    NOTICE.md                   남의 작업을 포팅한 것이라면 필수
```

⚠️ **`manifest.json`과 번호가 붙은 `prompt/` 디렉토리가 있었고, 지금은 둘 다 없다.**
manifest는 `aumos.json`이고 번들은 `PROMPT.md` 하나다. 이 저장소의 어떤 패키지도 옛
모양이었던 적이 없으며 `npm run lint`가 그것을 거절한다 — 지금의 모양은
[CONTRIBUTING.ko.md](contributing/CONTRIBUTING.ko.md)에 전부 적혀 있다.

**데이터 소스**는 Aumos가 자격증명을 쥐고 요청을 보낼 벤더다. 닿는 호스트, 투자자가 줘야
하는 것, 매니저가 물어볼 수 있는 엔드포인트를 적은 문서 하나. Aumos가 키를 쥐고 요청에
서명하고, 문서가 선언하지 않은 경로는 거절하고, 벤더가 보낸 것을 **읽지 않고** 그대로
돌려준다. 모든 필드가 리터럴이거나 숫자이거나 닫힌 enum의 멤버라, 문서도 패키지와
마찬가지로 실행 가능한 것을 표현할 수 없다.

```
sources/
  your-source-id/
    source.json            id, 호스트, 자격증명, 엔드포인트
    README.md              이 벤더가 무엇이고 키는 얼마인지
```

디렉토리 하나를 추가하는 pull request를 열면, 설치된 Aumos가 읽는 카탈로그의 엔트리가
된다. **이 저장소는 두 번째 종류의 제출을 받기 전까지 `aumos-agents`였다**(2026-08-16).
GitHub이 옛 이름을 리다이렉트하므로 기존 클론이나 링크는 그대로 동작한다.

열기 전에 **[CONTRIBUTING.ko.md](../contributing/CONTRIBUTING.ko.md)** 를 읽어라. 짧고,
규칙을 나열만 하지 않고 근거를 적은 곳이다.

## 머지된 제출에 무슨 일이 일어나나

Aumos는 하나의 생성기가 한 번의 패스로 각 카탈로그의 두 얼굴을 발행한다.

| | |
|---|---|
| `releases.aumos.app/agents/registry.json` | 기계가 읽는 패키지 인덱스. 각 발행 산출물의 SHA-256을 싣는다 |
| `aumos.app/managers` | 설치 전에 사람이 읽는 페이지 |
| `releases.aumos.app/sources/sources.json` | 기계가 읽는 데이터 소스 인덱스. 같은 방식이다 |
| `aumos.app/sources` | 그리고 그 페이지 |

어느 쌍도 서로 다른 카탈로그를 서술할 수 없다. 각각 하나의 목록에서 쓰이기 때문이다 —
그리고 이 저장소가 모든 목록을 만드는 두 곳 중 하나다. 다른 하나는 Aumos가 직접 싣는
것들이다. **패키지와 소스는 두 인덱스에 걸쳐 하나의 id 네임스페이스를 공유하고**, 그것이
하나의 폐기 목록으로 둘을 다 다스릴 수 있는 이유다 — 하나의 id는 하나를 뜻하고, 소스는
패키지가 쓰는 이름을 쓸 수 없다.

## 이 저장소가 아닌 것

- **코드를 두는 곳이 아니다.** 런타임도, 빌드도, 추가할 수 있는 의존성도 없다. 방법론이
  무언가를 실행해야 한다면 그것은 아직 ManagerPackage가 아니고, 데이터 소스가 응답을
  변형해야 한다면 그것은 문서가 할 일이 아니다. 형식을 우회하지 말고 이슈로 이야기해 달라.
- **리더보드가 아니고, 수익률에 대한 주장도 아니다.** 여기에는 패키지의 성과가 전혀
  기록되지 않는다. Aumos는 설치된 매니저를 투자자 본인의 장부 위에서 전방으로
  측정하고, 카탈로그에는 성과 수치가 **하나도** 실리지 않는다 — 그래서 이 페이지들에는
  무언가를 정렬할 근거가 없다.

## 폐기

머지된 패키지도 소스도, 이미 설치된 기계를 건드리지 않고도, Aumos가 발행하고 모든 설치본이
확인하는 **하나의** 폐기 목록을 통해 멈출 수 있다 — 목록이 하나인 것은 id가 하나이기
때문이다. 이미 봉인된 판단은 절대 다시 쓰이지 않는다.

## 라이선스

패키지마다 자기 `license` 필드를 싣고, 포팅된 것은 원본 고지를 안에 담는다. 이 저장소
자체의 파일(`tools/`, 워크플로우, 문서)은 MIT다.
