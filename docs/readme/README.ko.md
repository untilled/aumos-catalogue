# aumos-agents

<sub><a href="../../README.md">English</a></sub>

[Aumos](https://aumos.app) 에이전트 카탈로그의 제출 경로.

**AgentPackage**는 산문으로 쓴 투자 방법론이다. 어떤 데이터를 읽어도 되는지 선언하는
manifest, 그리고 어떻게 추론하는지 적은 프롬프트 번들. 코드는 없고 담을 수도 없다 —
발행 형식이 파일 경로를 텍스트에 대응시킨 JSON 문서라, 실행파일이 들어갈 필드 자체가
존재하지 않는다.

`agents/` 아래에 디렉토리 하나를 추가하는 pull request를 열면, 설치된 Aumos가 읽는
카탈로그의 엔트리가 된다.

```
agents/
  your-package-id/
    manifest.json          무엇을 읽어도 되는지, 그리고 저자가 대는 각각의 이유
    prompt/                방법론. 번호가 붙은 Markdown 단계들
      00-role.md
      …
      90-output.md
    README.md              어떻게 추론하는가 — 사람이 보고 고르는 페이지
    config.schema.json     선택
    NOTICE.md              남의 작업을 포팅한 것이라면 필수
```

열기 전에 **[CONTRIBUTING.ko.md](../contributing/CONTRIBUTING.ko.md)** 를 읽어라. 짧고,
규칙을 나열만 하지 않고 근거를 적은 곳이다.

## 머지된 패키지에 무슨 일이 일어나나

Aumos는 하나의 생성기가 한 번의 패스로 같은 카탈로그의 두 얼굴을 발행한다.

| | |
|---|---|
| `releases.aumos.app/agents/registry.json` | 기계가 읽는 인덱스. 당신 패키지의 발행 산출물에 대한 SHA-256을 싣는다 |
| `aumos.app/agents` | 설치 전에 사람이 읽는 페이지 |

둘은 서로 다른 카탈로그를 서술할 수 없다. 하나의 목록에서 쓰이기 때문이다 — 그리고 이
저장소가 그 목록을 만드는 두 소스 중 하나다. 다른 하나는 Aumos가 직접 싣는 네 개의
패키지다.

## 이 저장소가 아닌 것

- **코드를 두는 곳이 아니다.** 런타임도, 빌드도, 추가할 수 있는 의존성도 없다. 방법론이
  무언가를 실행해야 한다면 그것은 아직 AgentPackage가 아니다. 형식을 우회하지 말고
  이슈로 이야기해 달라.
- **리더보드가 아니고, 수익률에 대한 주장도 아니다.** 여기에는 패키지의 성과가 전혀
  기록되지 않는다. Aumos는 설치된 에이전트를 투자자 본인의 장부 위에서 전방으로
  측정하고, 카탈로그에는 성과 수치가 **하나도** 실리지 않는다 — 그래서 이 페이지들에는
  무언가를 정렬할 근거가 없다.

## 폐기

머지된 패키지는, 이미 설치된 기계를 건드리지 않고도, Aumos가 발행하고 모든 설치본이
확인하는 폐기 목록을 통해 멈출 수 있다. 그 패키지가 이미 봉인한 판단은 절대 다시 쓰이지
않는다.

## 라이선스

패키지마다 자기 `license` 필드를 싣고, 포팅된 것은 원본 고지를 안에 담는다. 이 저장소
자체의 파일(`tools/`, 워크플로우, 문서)은 MIT다.
