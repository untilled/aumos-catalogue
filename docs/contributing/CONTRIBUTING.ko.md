# AgentPackage 제출하기

<sub><a href="../../CONTRIBUTING.md">English</a></sub>

## 모양

`agents/` 아래 디렉토리 하나. 이름은 `manifest.json`의 `id`와 **정확히 같아야** 한다.
디렉토리 이름이 곧 패키지 id다 — 리뷰어가 트리를 읽는 것이 카탈로그를 읽는 것이 되도록.

```
agents/your-package-id/
  manifest.json
  prompt/00-….md … 90-….md
  README.md
```

pull request를 열기 전에 검사를 돌려라:

```bash
npm install
npm run lint
```

이것은 Aumos 저장소가 머지 시점에 돌리는 것과 **같은** 린트다. `tools/lint/` 아래 파일은
거기서 복사돼 온 것이고, 복사본이 원본과 달라지는 순간 저쪽 빌드가 깨진다.
[`tools/lint/VENDORED.md`](../../tools/lint/VENDORED.md)를 보라.

## 규칙과, 각각이 왜 있는가

아래 모든 규칙은 `npm run lint`가 강제한다. 하나하나가 무언가 깨진 뒤에 쓰였다.

### manifest가 권한 문서다

Aumos는 당신의 에이전트가 무엇을 할지 알아내려고 프롬프트를 읽지 않는다. 에이전트의
내부는 불투명한 것으로 취급되고, 패키지가 무엇을 해도 되는지는 `capabilities`에서만
나온다 — 그리고 그 목록은 **당신이 적은 이유**와 함께, 투자자가 결정을 내리는 화면에
그대로 표시된다.

`broker:write` 같은 capability는 없다. "거부된다"가 아니라 enum에 그 항목이 존재하지
않고, 거래하는 방법처럼 읽히는 이름의 capability는 거부된다.

### 어느 레인에서 도는지 말하라

| `lane` | 에이전트가 얻는 것 | 포기하는 것 |
|---|---|---|
| `closed` (기본) | 전부 Aumos Skill Gateway를 통해서 | 없음 — 읽은 모든 수치가 투자자가 나중에 다시 읽을 수 있는 근거로 기록되고, 판단이 고정된 시점보다 나중 날짜의 것은 하나도 없다 |
| `open` | 투자자 기계 위의 웹과 셸 | 근거, as-of 경계, 그리고 브로커 계좌에 연결될 수 있는 자격 자체 |

**closed** 번들은 자기가 들어 있는 프레임을 말해야 한다: `asOf`를 언급해야 하고, 오늘
가격을 보러 가라고 시켜서는 안 된다. 구조적으로 불가능한 일을 시키면, 트랜스크립트가
*시도한 적 없는 런*이 아니라 *차단된 유출*처럼 읽힌다.

**closed** 패키지는 `portfolio:read`도 요청해야 한다. 그것이 없으면 closed 에이전트는
아무것도 볼 수 없고, 장부에 대해 추론하는 번들은 보여준 적 없는 장부를 서술하는 것이 된다.

**open** 번들은 그 레인의 대가를 소리 내어 말해야 한다 — `evidenceIds`, `asOf`, 그리고
open lane 자체를 언급해야 한다. 아무것도 막지 않을 때 모델이 저지르는 실수 둘은 받은 적
없는 근거를 제출하는 것과 `asOf`를 장식으로 취급하는 것이고, 둘 다 조용히 실패한다.

### 모양을 **보여줘라**. 서술하지 마라.

가장 비싸게 치른 규칙이고, 세 번 모두 같은 방식이었다: 실제 `claude` 런이
`invalid-proposal`에 도달했고 엄격한 스키마가 판단 전체를 버렸다.

| | 무엇이 없었나 |
|---|---|
| 1 | `watches`가 산문으로만 서술되고 보여진 적이 없다 → 모델이 필드 이름을 지어냈다 |
| 2 | `WAIT` 예시만 있어서 `target`이 서술만 되고 보여지지 않았다 |
| 3 | `uncertainty`가 한 문장에서 이름만 불렸다 → 모델이 문자열로 추측했고 스키마는 배열을 원했다 |

그래서 린트는 **모양**을 검사하고 산문은 검사하지 않는다:

- **모든** decision action에 대한 worked JSON 예시 — `WAIT`, `WATCH`, `BUY`, `SELL`,
  `RESIZE`, `HEDGE`, `REBALANCE`. 문장 속 언급은 잃어버린 세 런이 이미 갖고 있던 것이다.
- 당신이 *이름을 부른* `rationale` 필드(`counterArguments`, `uncertainty`)는 fenced
  JSON 블록 안에서 배열로 보여져야 한다.
- `language`가 언급되고, 다른 언어로 된 worked 예시가 있어야 한다 — 단 JSON **키**는
  전부 ASCII로. 키까지 번역한 예시는 규칙이 아니라 실패를 가르친다.

### `{{INVOCATION}}`는 정확히 하나

번들 전체에서. 이걸 빠뜨린 번들은 어떤 자산에 대한 것도 아닌, 아름답게 구조화된 지시문을
보내고, 런은 아무도 묻지 않은 질문에 성공적으로 답한다.

### 남의 작업이면 그쪽 고지를 실어라

프롬프트를 포팅하면 2차적 저작물이 된다. 당신 패키지가 그렇다면 `manifest.json`에
`provenance` 블록이 실린다 — 그리고 라이선스 의무는 SPDX id가 아니라 **저작권 표시
줄**에 관한 것이므로:

- `provenance.notice`는 **당신 패키지 안의** 파일을 가리키고, 그 파일이 실제로 있다;
- 그 파일은 `provenance.licenseHolder`를 문자 그대로 포함한다;
- `provenance.commit`은 40자 전체 커밋이다. 브랜치 이름은 움직이고, 움직이고 나면
  아무것도 가리키지 않는다.

싣지 않은 provenance를 선언한 패키지는 로드되지 않는다. 이건 예의가 아니라 **라이선스**다.

### 전부 텍스트다

디렉토리의 모든 파일이 UTF-8 텍스트여야 한다. 바이너리도 심볼릭 링크도 안 된다. 발행
형식은 경로를 파일 내용에 대응시킨 맵이고, 그 외의 것은 담을 수 없다.

## 심사

우리가 머지한다. 이 규모에서는 의도된 병목이고, 병목이라고 적어둔다: pull request
리뷰는 사람이 보는 게이트이고, 사람이 보는 게이트는 그날 리뷰어가 가진 주의력만큼의
값어치가 있다. 그것으로 충분한 이유는 **여기엔 무언가를 숨길 코드가 없기 때문**이다.
이 저장소가 실행 가능한 것을 받아들이는 날, 그 논거는 성립을 멈추고 문이 열리기 전에
게이트를 다시 지어야 한다.

리뷰가 보는 것:

- **방법론이 구별되는가?** 같은 방식으로 추론하는 두 패키지는 한 패키지를 두 번 설치한
  것이고, Aumos는 그것을 별개의 행으로 측정한다 — 방법이 아니라 표본에서 온 차이를
  보고하게 된다.
- **README가 어떻게 추론하는지를 적고 있는가?** 투자자가 보고 고르는 페이지이고,
  카탈로그가 수익률을 일부러 보여주지 않는 만큼 방법론이 앞에 온다.
- **capability가 프롬프트와 맞는가?** 번들이 쓰지도 않는 데이터를 요청하는 것은 투자자가
  아무것도 아닌 것에 권한을 내주는 일이다.

## 버전

`version`은 semver다. `0.2.0`을 발행해도 `0.1.0`이 사라지지는 않는다 — 인덱스는 이
저장소에 있는 것을 싣고, id와 version 쌍은 한 번 발행되고 한 번 날짜가 찍힌다. 패키지를
바꾸는 같은 pull request에서 올려라.

## 여기서 하지 않는 것

- **지나가면서 당신 패키지를 고치지 않는다.** 발행되는 산출물은 당신 디렉토리의 모든
  파일이고 당신이 쓴 그대로이며, README는 카탈로그 페이지에 그대로 렌더된다.
- **아직 패키지에 서명하지 않는다.** 지금 발행 산출물과 인덱스 엔트리를 묶는 것은
  `registry.json`의 SHA-256이고, 서빙되는 바이트와 같은 바이트에서 한 자리에서
  생성된다. 서명이 필요해지는 조건은 인덱스와 산출물을 서로 다른 주체가 서빙할 수 있게
  되는 때이고, 그전까지는 digest가 그 일을 하고 폐기 목록이 발행 이후를 덮는다.
